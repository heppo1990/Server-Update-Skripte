# Offene Checkliste

- [ ] Nachinstallationsaufgabe nach Neustart und Wartungsfenster praktisch prüfen: wiederholte Ausführung bis zum Abschluss (spätestens nach fünf Tagen Ende), Neustartbedarf korrekt erkennen und beachten, Updates nur im Wartungsfenster installieren sowie genau eine Abschlussmail senden (Erfolg oder endgültiger Fehler).
- [ ] WinGet-Kompatibilität praktisch prüfen: Auf einem Windows-Server vor Server 2019 (einschließlich SBS) muss WinGet übersprungen werden, während Windows Update und Chocolatey weiterlaufen; auf Server 2019 oder neuer muss WinGet wie konfiguriert funktionieren.
- [ ] HTTP.sys-Clientzertifikataushandlung praktisch über die Verteilung prüfen: Auf einem Nicht-AD-Ziel mit WinRM HTTPS muss Port 5986 nach der Einrichtung `Clientzertifikat aushandeln: Enabled` zeigen und die Zertifikatsverbindung erfolgreich sein.
- [ ] PSGallery-Offlinepaketbereitstellung nach Korrektur von `Save-Module` prüfen: Die Verteilung muss die Module online samt Abhängigkeiten zwischenspeichern und darf den Offline-Fallback-Hinweis bei erfolgreichem Abruf nicht ausgeben.
- [ ] Check und Installation auf einem Ziel ohne NuGet-/PSGallery-Zugriff prüfen: aktuelle Module und NuGet-Provider zuerst zentral online beschaffen und offline übertragen; erst bei fehlendem Onlineabruf Offline-Fallback verwenden und Updateabfragen ohne rohe PackageManagement-Warnungen fortsetzen.
- [ ] Modulpflege praktisch prüfen: Bei aktuellen PSWindowsUpdate-/Microsoft.WinGet.Client-Versionen dürfen keine Pakete heruntergeladen oder übertragen werden; veraltete Versionen müssen weiterhin aktualisiert werden. Ein aktueller NuGet-Provider darf nicht erneut kopiert oder importiert werden.
- [ ] WinGet auf SRVDOM01 erneut prüfen: Bei einer leeren Suche darf die bereits registrierte aktuelle `Microsoft.Winget.Source`-Version nicht nochmals per AppX installiert werden; die Suche muss in einer frischen Verbindung erfolgreich enden.
- [ ] WinGet-Check auf TP-M08 mit angemeldetem Benutzer prüfen: Benutzerbezogene Updates (insbesondere VS Code User) müssen trotz Remoting als `TP-M08\UpdateUSR` im Check und Bericht mit dem installierenden Benutzer erscheinen.
